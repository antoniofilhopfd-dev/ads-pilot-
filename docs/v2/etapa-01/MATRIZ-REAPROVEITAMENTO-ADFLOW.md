# Matriz de reaproveitamento — AdFlow → AdsPilot

**Fonte auditada:** `adflow.zip.zip` enviado em 11/10/2026 (contém `adflow-codigo-completo.zip` e `adflow-export.zip`, idênticos exceto um `.DS_Store`). **Auditoria estática** (leitura de ~7,5 mil linhas de `src/lib`, schema Prisma, rotas, MCP e componentes). O AdFlow **não foi executado** (não houve `npm install`/execução de código de terceiros); portanto não há prints do AdFlow.
**Varredura de segredos no pacote:** nenhum token/chave/`.env`/banco. Único ponto: o `seed` cria `admin@example.com` / `demo1234` — **nunca replicar**.
**Licença:** o pacote não traz `LICENSE`. Parte-se da premissa de que o código é seu (projeto próprio); dependências (Next, Prisma, NextAuth, Recharts, Leaflet, Zod…) têm licenças permissivas (MIT/Apache-2/ISC/BSD). **Confirme a titularidade** antes de publicar comercialmente.

## O AdFlow em uma frase
Painel **monousuário** (papel único `ADMIN`), Next 16 + Prisma/SQLite + NextAuth, **uma conta Meta global por variável de ambiente**, valores em centavos, Graph API v21.0, criação de campanha **direto na Meta** (sempre `PAUSED`), alertas calculados na hora (sem estado), notificações/WhatsApp com Evolution API, MCP por **stdio sem autenticação** compartilhando o banco.

## Diferenças de arquitetura que impedem copiar "como está"
| Tema | AdFlow | AdsPilot (preservar) |
|---|---|---|
| Multiempresa | inexistente (1 usuário, 1 conta) | organizações, perfis, acesso por conta, isolamento testado |
| Credencial Meta | `META_ACCESS_TOKEN` global em env | token por organização, criptografado (AES-256-GCM) |
| Token na requisição | **na URL** (`access_token=` em GET) → vaza em logs/proxy | cabeçalho `Authorization` |
| Sem credencial | "modo simulado" devolve **sucesso sintético** com IDs falsos | proíbe simular criação real; demonstração sinalizada e separada |
| Banco | SQLite, JSON em string, mídia em base64 no banco | MySQL, tipos reais; mídia com limites |
| Auth | NextAuth credenciais, JWT | sessões próprias com hash, reset, rate limit |
| MCP | stdio, sem auth, `confirm:true` | HTTP, token por usuário, escopos, **código humano** |

## Problemas de segurança/qualidade do AdFlow (para não importar)
Token da Meta na query string · "sucesso simulado" com IDs falsos · efeitos colaterais em requisições `GET` (notificações/marcos) · envio de WhatsApp sem idempotência · limites de alerta apresentados como "benchmarks" sem fonte · referências pessoais e domínio fixo no código · imagens em base64 no banco · API v21.0 defasada · seed com senha conhecida.
